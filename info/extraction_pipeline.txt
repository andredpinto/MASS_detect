FULL EXTRACTION PIPELINE (LIDC -> LNDb -> PyRadiomics -> optional cleanup)
=======================================================================
Run all commands from the repository root.

0. SETUP (once per machine)
---------------------------
$ uv sync                      # main environment (Python 3.10)

LIDC scripts need a separate environment (pylidc is from 2018 and does not work
with the numpy>=2.2 that the main environment requires):
$ uv venv .venv-lidc --python 3.10
$ uv pip install --python .venv-lidc/bin/python "numpy==1.23.5" "pylidc==0.2.3" "setuptools<82" "SimpleITK" "pandas" jupyter

Data that must exist beforehand:
- LNDb CTs in data/LNDb/ and radiologist masks in data/LNDb/masks/
- LIDC DICOMs in data/LIDC/lidc_idri/
- training CSVs (extract data/trainset_csv.zip): trainNodules_gt.csv, testNodules.csv, ...

1. LIDC  --  nodule volumes + consensus masks   [run with .venv-lidc]
-------------------------------------------------------------------
$ .venv-lidc/bin/python -m src.mass_detect.scripts.lidc_preprocessing

Writes data/nodules/train/<patient>_nodule<k>.mhd + <patient>_nodule<k>_mask.mhd
plus meta_info_lidc.csv (malignancy labels). Processes the whole LIDC-IDRI
(output dir = OUTPUT_DIR constant at the top of the script) and is resumable
(existing pairs are skipped) — expect it to take a while.

2. LNDb  --  30 mm cubes + nodule masks
---------------------------------------
$ uv run python -m src.mass_detect.scripts.lndb_preprocessing --findings-csv data/trainNodules_gt.csv --split train --out-dir data/lndb_nodules
$ uv run python -m src.mass_detect.scripts.lndb_preprocessing --findings-csv data/testNodules.csv    --split test  --out-dir data/lndb_nodules

Writes <out-dir>/<split>/LNDb-XXXX_noduleY.mhd + _mask.mhd + meta_info_lndb.csv.
(--out-dir keeps the LNDb cubes apart from the LIDC ones; the default is data/nodules.)
For the train split the manifest also carries malignancy and is_cancer, read from
notebooks/lndb_processed.csv and bound to each finding by position (within 3 mm),
not by id: that file's finding_id is the radiologist's own number, not the nodule id
of trainNodules_gt.csv, so joining on it would rate the wrong nodule. Use
--labels-csv "" to skip and --label-radius to widen the match.
The test split needs the test CTs (extract testdata*.rar into the CT dir) and, as
written, the mask step expects the RadID/RadFindingID columns that only the train
CSV has. Add --limit N to try a few CTs first.

3. PYRADIOMICS  --  feature table
---------------------------------
$ uv run python -m src.mass_detect.scripts.extract_features_pyrad \
    --input data/nodules/train      --dataset LIDC --split train \
    --input data/lndb_nodules/train --dataset LNDb --split train \
    --input data/lndb_nodules/test  --dataset LNDb --split test \
    --params Params.yml --output data/radiomics_features.csv --jobs 12

One --input/--dataset/--split triple per folder of nodule .mhd + _mask.mhd pairs;
the dataset labels must be exactly "LIDC" and "LNDb" (the notebooks filter on
them). Resumable (nodule ids already in the CSV with status=ok are skipped;
--force re-extracts everything). Feature settings live in Params.yml.

4. (OPTIONAL) CLEANUP  --  EDA + feature filtering
--------------------------------------------------
$ uv run jupyter notebook notebooks/01_radiomics_features_analysis.ipynb

Reads data/radiomics_features.csv, checks QC (resampling, missing values, constant
and correlated features) and writes data/radiomics_features_processed.csv,
data/radiomics_kept_features.csv and data/radiomics_processing_report.csv —
the inputs for the modelling notebook (notebooks/02_train_model_and_predict.ipynb).
